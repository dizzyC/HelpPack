# 诊断与修复计划验收记录（2026-10-02）

本轮仅本地开发和打包，不提交、推送或创建 Release。保留既有 Git 历史以及本轮开始前的中文版功能修改。英文版同时沿用相同修复逻辑，文案集中在 `plan_resources.py`。

## 现状审计与修改

原有可运行能力：诊断引擎/后台线程、单项修复动作接口、受限 UAC 辅助进程、DPAPI 备份、脱敏历史、网络与软件专项检查、目录占用、外设、时间线、监测、截图副本及求助包导出。

原有缺陷：代理或自定义 DNS 存在即建议重置；运行正常的服务也被推荐重启；旧回滚没有修改后状态冲突检查；性能检查只有短时样本；软件事件主要匹配本地化文字；没有证据驱动的计划调度和计划级取消。已移除这些不安全建议，增加结构化服务依赖检查、修改后快照比对、六次连续采样、结构化崩溃字段和计划执行器。

只有有限实现、不能作为完成验收的能力：厂商驱动下载/安装和真实设备回退未完成验证，本轮从修复入口排除自动驱动安装；网络栈损坏、服务无响应、组件损坏尚无足够可靠的自动证据生成器，不提供无效修复按钮。

## 操作入口与流程

首页 → 本机诊断 → 选择场景；网络可输入标准端口 HTTPS 目标并选择所有网站/单站/Wi-Fi 场景。专项检查还支持指定 DNS 对比和选择正在运行程序或 EXE。

诊断结果页 → 查看修复计划 → 逐项选择 → 确认执行；可能中断操作的项目默认不选，并额外单独确认。执行前重新检查适用条件，计划五分钟过期，检查结果过期也不会生成新计划。同一时刻只运行一个计划；失败的依赖项阻止其后续动作，独立项目继续。取消只停止调度，不强杀正在写系统的进程。完成后分别展示指标、相关场景复查及改善/仍异常/失败/待重启/未知，不替用户判定问题已解决。

无适用动作时仍可打开计划说明及 Windows 网络/应用/打印设置。可通过“恢复本次修改”或“恢复本应用之前的修改”选择有有效修改后快照的备份；恢复前比对当前状态，冲突时拒绝覆盖。旧备份缺少修改后快照时不自动恢复。

## 当前动作能力表（真实修复均未在开发电脑执行）

| 动作 | 本轮真实入口及适用条件 | 确认与权限 | 回滚 |
|---|---|---|---|
| 刷新 DNS 缓存 | 两个参考域名均解析失败时生成；执行前重新检测 | 计划确认 + 按需 UAC | 不可恢复原缓存；不改变 DNS 服务器 |
| 启动声音/蓝牙/打印/更新服务 | 相关场景、服务为自动启动且已停止；依赖须已运行 | 计划确认 + 按需 UAC | 尽力恢复为停止；不能恢复任务；有运行依赖时拒绝停止 |
| HelpPack/VS Code 缓存隔离 | 本次另有异常/持续资源压力证据，精确白名单缓存目录，应用已关闭，无链接，最多 5000 项/512 MiB；缓存存在本身不生成计划 | 计划确认 | 保留原字节与 SHA-256；原目录被重建或备份改变时拒绝覆盖 |
| 禁用所选 HKCU Run/RunOnce 项 | 既有启动项检查提供；用户明确选择具体项 | 单独确认；当前用户权限 | DPAPI 原状态，冲突时不覆盖 |
| 恢复本应用以前的 DNS/代理/启动项/缓存/服务修改 | 仅本应用有效备份；修改后状态仍匹配 | 先恢复确认；DNS/服务另行确认并按需 UAC | 恢复原状态；恢复动作本身不承诺再次撤销 |
| DHCP 续租、DNS 恢复 DHCP、代理重置 | 执行器及单项接口保留并加固；没有充分异常证据时不生成计划 | 必须另行确认；适配器白名单与新状态检查 | 续租不可回滚；DNS 保存 IPv4/IPv6 自动/手动状态；代理有备份 |
| 服务重启、SFC/DISM | 后端接口保留；缺少可靠无响应/组件损坏证据时仅人工建议 | 必须另行确认；管理员权限 | 不可靠回滚；不能恢复中断任务或系统组件 |
| 适配器禁用/重启、Winsock/网络栈、结束程序、取消打印任务 | 本轮没有安全自动执行入口，明确人工处理 | 不显示假修复按钮 | 不作自动恢复承诺 |

缓存同盘保留恢复副本**不会释放磁盘空间**，这是可恢复的缓存重建辅助，不是磁盘清理工具。代理/PAC/自定义 DNS 配置本身不是异常。系统时间只展示本机值，不能证明绝对时钟偏差。HTTPS 不绕过证书验证；PAC/WPAD 和浏览器完整路径仍有限。

## 验证方法和范围

- 自动化覆盖：无异常/正常配置不修复、未确认、单独确认、过期/篡改、权限拒绝、条件改变、错误/超时、取消、依赖、冲突与重复执行、复查、回滚冲突、缓存恢复、参数注入、历史/报告脱敏。
- 实际 Windows 原生 Qt 源码及单文件 EXE 通过 `--plan-self-check <输出目录>` 验收：后台只读网络和资源检查、真实窗口/窄窗口渲染、长文字、虚构计划预览后取消、Unicode Markdown/ZIP 与 manifest SHA-256。
- 系统修改只用 Mock；缓存移动/恢复只用测试创建的临时文件；DPAPI 只测试虚构数据。未在开发电脑修改 DNS、代理、启动项、服务或系统文件。
- 未完成可还原 Windows 虚拟机真实修复验收、UAC 实际接受/拒绝点击、外部鼠标完整流程、英文 Windows 实机和物理外设验证。不能把模拟通过称为真实修复通过。
- 修复命令超过截止时间时记录超时，但为避免损坏系统仍等待已有进程完成；等待过程中可以停止后续调度，不承诺强制终止或精确进度。

具体最终测试数量、产物和 SHA-256 见同目录 `repair-plan-results.md`。输出、截图和虚构 ZIP 均位于忽略的 `dist/`，不进入源码或 GitHub。

服务使用 CIM/结构化状态，不依赖中英文 `sc` 文本；崩溃字段读取事件 XML，缺失字段保留未知而不是猜测原因。参考：[Microsoft Start-Service](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.management/start-service)、[Microsoft 崩溃事件说明](https://learn.microsoft.com/en-us/troubleshoot/windows-server/performance/troubleshoot-application-service-crashing-behavior)。
